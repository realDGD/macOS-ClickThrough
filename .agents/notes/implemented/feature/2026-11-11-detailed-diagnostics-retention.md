# Agent Note: 可选详细诊断与自动清理

Status: implemented

## Problem

间歇性窗口无法激活时，原日志仅记录成功命中并通过筛选后的 AX 请求，无法区分点击没有进入回调还是在早期被放行。原来每进程达到 2 MiB 后停止写入，可能错过后续故障，旧文件也会持续积累。用户要求详细日志作为正式版本的可选功能，并保持自动清理。

## Decision

保留原“记录诊断日志”开关，新增默认关闭的详细开关。普通模式保留生命周期、故障及 AX 请求结果；详细模式额外记录每次 down 到达、跳过原因、事件年龄与分段耗时。选择保存在现有设置中，旧版本数据缺少新字段时按关闭迁移，保留其他偏好。

两级共用正式产品实现，不使用诊断包专用编译开关。窗口 AXMain → 应用 AXFrontmost → 放行同一原事件的顺序、25 ms AX 消息超时和修饰键政策不变；不增加 AX 查询、激活重试或事件重放。

日志编码、写入及清理在后台串行队列执行。单文件最多 2 MiB，达到上限时轮换并继续记录；总计最多 20 MiB，超出时淘汰最旧文件。启动（包括日志关闭时）和写入时删除 7 天未更新的日志。只处理专用目录中的 `session-*.jsonl` 普通文件，跳过符号链接和无关文件，研究及原始证据目录不受影响。

## Alternatives considered

- 始终记录详细信息：增加日常日志量和采集开销，采用独立可选开关。
- 仅提供临时诊断包：后续更新可能失去捕捉能力，采用同一份产品源码。
- 达到上限就停写或无限保留旧日志：分别会丢失后续现场或持续占用磁盘，采用文件轮换、容量及年龄限制。
- 增加清理服务或大量可调参数：当前没有需求，复用日志队列和固定保留策略。

## Consequences

详细模式增加元数据与异步磁盘工作，但输入回调不等待磁盘；不会记录键盘输入、剪贴板、网页正文或窗口标题。超过年龄或容量的日志会自动删除，需要长期保留的证据应复制到日志目录之外。关闭日志不立即删除全部文件，过期清理在下一次启动或写入时执行。

文件操作实现位于 ClickThroughCore，便于在临时目录测试筛选、权限、轮换、过期清理、总容量与清理范围。设置迁移另有检查。测试、构建与签名通过不证明间歇性激活故障已修复；实际证据见[验证记录](../../../../docs/validation/INTERMITTENT_ACTIVATION_2026_11_11.md)。
