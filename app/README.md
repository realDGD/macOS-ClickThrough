# ClickThrough 应用

原生 macOS 菜单栏应用，最低部署目标 macOS 14，当前包为 arm64。A4 主路径使用窗口 AXMain → 应用 AXFrontmost，并保留同一个真实鼠标事件；目标窗口会正常激活并前移。

## 使用

首次启动处于关闭状态。左键菜单栏图标切换功能；右键显示设置和退出。为 ClickThrough 单独授予辅助功能权限后，再点击开启。原 PoC 的授权不能直接沿用。

点击“开启”或菜单栏图标时，若缺少辅助功能权限，会直接请求系统授权并打开对应设置，与“打开辅助功能设置…”按钮使用同一入口。授权后再次点击开启；自动启动不会主动弹出授权请求。

- 关闭和运行图标分别使用 `cursorarrow.click`、`cursorarrow.click.2`。在新系统上，它们对应 `pointer.arrow.click` 系列；保持已调整的图标字号。
- 隐藏图标后继续运行。从 Spotlight 或 Finder 重新打开软件，恢复图标且保持功能开关。登录启动保留隐藏设置。
- 黑名单忽略所列应用，空列表处理所有符合条件的应用。白名单只处理所列应用，空列表全部跳过。两份列表独立保存，按 bundle ID 匹配。
- “右键菜单跟随点击屏幕”默认开启：ClickThrough 的菜单显示在点击屏幕的菜单栏下方，独立于首次点击增强开关。关闭后使用系统默认定位；选择会保存并在后续更新时沿用。该选项只控制本应用菜单，无法计算定位时也使用系统默认定位。
- 登录项使用 SMAppService，只在用户切换时注册。系统要求批准时提供入口；移除软件前先关闭登录启动。
- 修饰点击保留系统行为；当前沿用 A4 对 Caps Lock、Fn 等标志的过滤。特殊窗口层、自身和命中失败的点击直接通过。
- 系统暂停监听后不循环重启；图标显示非运行状态，用户可手动重新开启。

菜单栏图标反映实际引擎状态，不根据“用户想开启”就显示已运行。AX 支持和目标应用事件处理可能限制首次点击效果；[测试说明](../docs/testing.md) 列出已有证据和未验收范围。

## 本地数据

bundle ID 为 `local.clickthrough.app`，设置保存在相应 UserDefaults。诊断默认关闭；开启后写入 `~/Library/Logs/ClickThrough/session-*.jsonl`，不记录键盘输入、剪贴板、网页正文或窗口标题。

- **记录诊断日志**：记录启停、监听故障、目标窗口与 AX 请求结果、点击处理总耗时。
- **记录详细诊断日志**：需同时开启上述开关；额外记录每次鼠标 down 到达、跳过原因、事件年龄及窗口命中／AX 步骤耗时。详细模式默认关闭，选择会保存并在后续启动、更新时沿用；旧版本设置升级后仍保留，详细模式初始关闭。
- 日志文件达到 **2 MiB** 时自动轮换并继续记录；总占用最多 **20 MiB**，超出时从最旧文件开始清理。应用启动（包括诊断关闭时）和日志写入时，自动删除超过 **7 天未更新**的日志。清理只针对日志目录内的 `session-*.jsonl` 普通文件，不处理符号链接、无关文件或项目内的研究记录。需要长期保留的证据请复制到日志目录外。

AXFrontmost 的即时读回不是激活完成屏障，不能单凭返回成功或前台值判定实际点击成功。日志编码、写入、轮换和清理均在后台串行队列执行；输入回调仅提交可选诊断，不等待磁盘操作。普通和详细模式均为正式产品功能，后续构建使用同一份实现。

普通本地构建默认使用 ad-hoc 哈希身份；Homebrew 下载固定源码后用独立 CLT 编译，并采用固定标识身份。首次签名策略迁移可能需要用户重新关联辅助功能授权；它不认证开发者，也不提供 Apple 公证。不要同时运行开发副本和另一份已安装实例。
