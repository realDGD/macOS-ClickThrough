# Phase 1 已有测试结论

整理日期：2026-10-15，Asia/Makassar。本轮实验已停止。本文只整理现有物理操作、业务日志和历史源码记录；本次整理没有增加鼠标试次、重新构建探针或安装软件。

后续状态：用户已要求以 A4 进入 Phase 2，现有证据用于 [架构决策](../architecture/PHASE_2_A4.md)。下文“尚未确定架构”“不进入正式开发”保留为本轮实验收尾时的历史状态；不 raise 另行研究已暂停。未通过项没有因阶段推进而改记为通过。

## 结论

**公开 API 请求窗口／应用激活，再放行真实事件，在已测场景中可使原本失效的首次点击执行操作。A4 是现有证据最充分的候选。** 证据支持这一技术方向的局部可行性，尚不足以承诺全应用覆盖、长期可靠性或生产性能，也不意味着已经确定最终架构。

A4 在真实鼠标 down 的回调中，先请求命中窗口的 `AXMain`，成功后请求应用的 `AXFrontmost`，再放行同一事件。没有重放鼠标事件、调用 `AXPress` 或针对复制按钮编写应用专用逻辑。关键试次的 down/up/drag 日志记录原事件字段未变；这不能进一步证明下游应用不会重新解释事件。

## 保留的限制与未验证范围

- Safari 曾有 6 次 `AXFrontmost` 可写性查询、2 次即时读回返回 `-25204`。这些错误不能解释成静态不支持，也不能依据用户成功反馈反推每次错误都没有影响。原记录保留，不为消除错误追加测试或修改路径。
- AX 写入成功、即时读回、前台 PID 都不是“真实事件之前激活已经完成”的保证；成功的依据仍是实际业务执行。具体时序假设没有独立证实。
- 短间隔点击同一后台按钮曾出现额外 DOM click；停止／完全退出探针和 observe 条件下也复现。已有配对支持额外 click 出现在所观察的 session tap 之后，未定位具体生成者，不能宣称已修复，也不能简单归因于鼠标或 A4。
- 当前干预仅覆盖无键盘修饰键、普通窗口层的左右 down；其他事件原样放行。修饰键、精确命中边界、复杂窗口及完整鼠标语义仍属未验证范围。
- 未完成 CPU、端到端延迟及长期稳定性评估。单对象 25 ms AX 消息超时不是总回调延迟上限；`callback_work_ns` 也不含后续日志的全部成本。
- Firefox 没有完成物理试次；VS Code 只确认了已安装的 Electron 框架身份，尚无试次；SwiftUI 无已完成验证。均不补写为通过，也不因此扩大本轮测试。
