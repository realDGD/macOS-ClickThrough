# 测试与证据

## 与改动相关的自动检查

```sh
make test
make test-release APP=app/build/ClickThrough.app
```

Swift 单元检查覆盖应用规则、手动／登录图标恢复、状态与图标、修饰标志、失败开启意图和 AX 步骤顺序。分发检查在临时签名副本中验证参数、归档校验值、最低系统声明和旧 Cask 清理，不修改运行包。

使用新目录候选包时，将 `APP` 指向该包。已安装 Homebrew 的环境可运行 `make test-homebrew APP=路径/ClickThrough.app`，额外解析真实 Cask DSL；不注册 tap、不安装软件。

构建验证另见 [开发指南](development.md)。包的最低版本应同时核对 Info.plist 和 Mach-O `minos`，字符串图标还需检查系统符号可用性，不能只依赖编译器。

## PR CI

[CI 工作流](../.github/workflows/ci.yml) 在 PR、main 推送和手动触发时，使用 macOS 15、26 的 arm64 runner 运行现有单元测试、应用构建、最低部署版本／资源核对及 Homebrew Cask DSL 检查。权限仅为源码读取，不使用签名凭据，不启动应用，不发布产物或操作登录项／TCC。GitHub runner 所带 Xcode 用于 CI，本机独立 CLT 的构建证据另见 [验证记录](validation/CI_CLT_2026_10_16.md)。

这些检查证明构建与打包行为，不替代真实鼠标业务验收，也不等于 macOS 14 实机通过。

## 真实鼠标回归

关键业务由用户物理输入和独立靶标日志证明，界面自动化用于准备和状态读取。最近一次 [小范围物理回归](validation/PHASE_3_PHYSICAL_2026_10_15.md) 在平台调整前的正式包完成，覆盖单击、双击、拖出取消／恢复、右键操作与菜单栏开关。该结果不会自动成为新候选包或旧系统的实测结果。

macOS 14 平台调整阶段只执行部署、图标和打包相关检查，未新增应用、浏览器、登录重启或权限实验。[兼容改动验证](validation/MACOS14_2026_10_15.md) 记录具体构建和核心哈希。

随后经用户授权，将带图标的 0.1.0 (3) 安装至“应用程序”，完成本机 macOS 27 的[同进程撤权恢复](validation/PERMISSION_RECOVERY_2026_10_15.md)：基线后台单击 0→1；撤权后后台单击 1→1、前台单击 1→2；重新授权并手动开启后后台单击 2→3。独立靶标业务日志与产品请求对应，全程未重启或更换二进制。此结果仅覆盖同一构建、同一进程的这一轮恢复。
