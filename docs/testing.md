# 测试与证据

## 与改动相关的自动检查

```sh
make test
make test-release APP=app/build/ClickThrough.app
make test-release-tools
make test-signing APP=候选目录/ClickThrough.app
```

DMG 检查仅挂载临时副本，不打开 Finder 或启动应用，并在结束时卸载。

`test-signing` 只对临时副本执行真实 `codesign` 检查，验证默认／固定签名身份、跨版本匹配及错误输入，不安装或启动应用，也不修改系统授权。2026-11-06 的[固定身份试验](validation/FIXED_SIGNING_IDENTITY_2026_11_06.md)通过离线检查，并在本机 macOS 27.2 / arm64 完成首次授权迁移与 6001 → 6003 实际代码更新：系统授权记录完全未变，新进程直接开启成功。验收后功能关闭且进程退出；未做全量回归，也未撤权重测新增的手动开启授权提示分支。该次试验没有切换默认签名；后续 [Homebrew 源码构建](validation/SOURCE_HOMEBREW_2026_11_06.md)在该安装路径采用固定标识签名，普通本地及手动 DMG 默认值保持原样。

Swift 单元检查覆盖应用规则、手动／登录图标恢复、状态与图标、修饰标志、失败开启意图和 AX 步骤顺序。分发检查在临时签名副本中验证参数、归档校验值、最低系统声明和旧 Cask 清理，不修改运行包。

诊断检查在临时目录运行，覆盖普通／详细模式筛选、旧设置升级与新设置持久化、2 MiB 文件轮换后继续写入、7 天过期清理（包括诊断关闭时启动）、20 MiB 总容量下淘汰最旧日志、无关文件与符号链接保留，以及超大单条记录后的写入恢复。不操作真实日志目录，不启动输入监听。

使用新目录候选包时，将 `APP` 指向该包。已安装 Homebrew 的环境可运行 `make test-homebrew APP=路径/ClickThrough.app`，额外解析真实 Cask DSL；不注册 tap、不安装软件。

`test-release-tools` 覆盖有效发布、版本不匹配、DMG 被修改、二进制中的个人路径与凭据模式、意外诊断文件及附加 Ruby 代码等输入。发布工作流对实际 DMG 运行同一校验，并在只读挂载时核对应用签名、执行权限、arm64 架构和 Mach-O 最低版本；不安装或启动应用。

`test-release-tools` 还用临时本地 Git 仓库检查源码 Cask 的新版本提交／推送、同版本幂等、数字版本防降级、同版本内容不可改写、源码提交核对及无关修改隔离；检查来源 URL、校验值及附加 Ruby 的拒绝。源码 Cask 的可信模板与真实 Homebrew DSL 往返另有小范围检查；没有 Homebrew 的环境明确跳过 DSL 检查，不安装软件。当前迁移证据见[源码 Homebrew 验证](validation/SOURCE_HOMEBREW_2026_11_06.md)。历史 DMG 自动同步与公开事件证据仍保留在[原记录](validation/TAP_AUTO_SYNC_2026_10_16.md)和 [v0.1.1 发布记录](validation/RELEASE_0_1_1_2026_10_16.md)，不将其转记为新流程实测。

构建验证另见 [开发指南](development.md)。包的最低版本应同时核对 Info.plist 和 Mach-O `minos`，字符串图标还需检查系统符号可用性，不能只依赖编译器。

## PR CI

[CI 工作流](../.github/workflows/ci.yml) 在 PR、main 推送和手动触发时，使用 macOS 15、26 的 arm64 runner 运行现有单元测试、应用构建、最低部署版本／资源核对及 Homebrew Cask DSL 检查。权限仅为源码读取，不使用签名凭据，不启动应用，不发布产物或操作登录项／TCC。GitHub runner 所带 Xcode 用于 CI，本机独立 CLT 的构建证据另见 [验证记录](validation/CI_CLT_2026_10_16.md)。

这些检查证明构建与打包行为，不替代真实鼠标业务验收，也不等于 macOS 14 实机通过。
