# 固定签名身份与升级授权试验

日期：2026-11-06。用户要求参照 Remote2Prompt 的无证书固定身份方案尝试保留 ClickThrough 更新后的辅助功能授权。

## 范围

新增显式选择的 `CLICKTHROUGH_STABLE_ADHOC_IDENTITY=1` 构建模式，设置 `designated => identifier "local.clickthrough.app"`；默认构建与公开发布工作流保持原来的哈希身份。只调整构建签名，不修改 A4 或其他应用运行逻辑，不自动授予权限、重置 TCC、创建证书或修改登录项。该模式只检查标识，不验证发布者身份，其他程序也能声明同一标识。

本轮开始时，已安装版为 0.1.3 (6)，默认 ad-hoc 身份为 `cdhash`。发现既有 ClickThrough 进程运行且开启意图为 true；先保留现场及原包备份，不根据旧会话的关闭记录改变现状。公开 CG 显示器查询显示未息屏，但这不等于用户已在场配合。已有不 raise 研究及未提交修改保留。

## 验证状态

- 固定身份候选与默认模式均构建成功、严格验签通过；默认模式实际仍为 `cdhash`，没有隐式启用新规则。
- `make test-signing` 五组临时副本检查通过：默认哈希拒绝不同版本；固定规则接受不同代码哈希并确认首次迁移不兼容旧规则；非法选项不改变原签名；错误标识被拒绝；内容篡改被严格验签拒绝。检查没有启动应用或修改权限。
- 已保留两个实际测试候选：0.1.3 (6001) 的代码哈希为 `b5b9c156540897fdc3a74d71ca2ee51647077397`，0.1.3 (6002) 为 `6557d76f61aaeac85bce000a0bcb07f6aa9d0ba0`，二者均为相同的显式固定身份。两包签名前只改变构建号，没有改变业务源码；代码哈希不同不代表 A4 逻辑发生变化。
- 只读系统 TCC 查询确认旧辅助功能记录为 Allowed，要求仍是旧包的 `cdhash`，不能匹配任一固定身份候选。用户级数据库不可读不影响本次系统级辅助功能记录核对。
- 用户已停用并退出旧进程；首个固定身份候选 0.1.3 (6001) 安装到原路径后，由用户在“设备控制和数据访问”重新关联授权。系统实际保存要求已变成固定 `identifier "local.clickthrough.app"`，并观察到首个候选显示“已开启”。代理随后关闭功能并退出，没有切换系统权限。
- 用户追加“点击开启遇到缺权限时直接弹出授权入口”。`AppModel.setEnabled` 仅在用户开启且引擎返回 `permissionRequired` 时调用现有 `openAccessibilitySettings()`；设置按钮和菜单栏入口共用该路径，自动启动不主动请求授权。新代码编译通过，未另行撤权测试该分支。
- 实际更新采用包含此小改动的 0.1.3 (6003)，代码哈希为 `a4891a88457bdf6c437a927951ab9b3dfa35539c`。6002 保留为未运行的旧候选，未将其记为实机通过。
- 在本机 macOS 27.2 / arm64，将 6001 换成 6003 后，系统辅助功能授权值、身份要求原始数据及修改时间均未变；新安装包满足系统已保存的要求。用户没有再次授权，直接点击“开启”，新进程原生界面显示“已开启”。该状态只在原生 AX 可信检查、tap 创建及启用成功后设置，因此本轮实际更新后的有效权限检查通过。
- 旧哈希授权与新固定规则不兼容；首次迁移授权不计为“跨升级保留通过”。其他系统版本不在本轮验收范围。

验收后已关闭功能并退出，`wantedEnabled=false`，没有剩余 ClickThrough 进程；除开启意图外，其他设置与初始基线一致，登录项未修改。原安装包、已运行候选及日志保留。A4 引擎、窗口命中与激活源码未变，应用运行源码仅修改上述手动开启入口。

遵照用户简要验证要求，未运行全量回归、重新验证业务点击或扩展系统矩阵。结果仅覆盖本机这一次固定身份的实际代码更新，不保证其他系统或签名策略变化后的行为。当前安装的是试验候选，默认／公开发布构建仍使用原哈希身份；后续采用原发布包不能据此保证沿用这次授权。本记录不包含公开发布结果。
